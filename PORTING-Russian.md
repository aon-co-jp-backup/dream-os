# PORTING.md — Руководство по переносу dream-os (сжатая версия)

> **Примечание**: Это сжатый перевод. Полное руководство по дереву
> файлов и зависимостям путей по-прежнему доступно только на японском
> (с примесью английского) в [PORTING.md](PORTING.md) — обращайтесь
> туда перед реальным переносом.

**Область**: `dream-os` — репозиторий на концептуальной стадии для
слоя прикладных сервисов / слоя абстракции GPU для Windows, macOS,
Android и различных дистрибутивов Linux (с Sony PlayStation 5/6 и
Nintendo Switch 2 как будущими целями).

Сводка переиспользуемых шаблонов реализации из этого проекта на
случай их переноса в другой проект:

1. **Повторное использование существующих кроссплатформенных бэкендов
   Vulkan** (`opencuda-vulkan` из `open-cuda`) как общего слоя
   выполнения вместо написания новых ядер с нуля — шаблон повторного
   использования через зависимость по пути, применяемый в
   `dream-os-kernel` систематически.
2. **Программное управление duty-cycle энергопотребления**
   (`MiningPowerProfile`) как нейтральная к производителю альтернатива
   API ограничения мощности в стиле NVML, когда целевой GPU их не
   предоставляет (подтверждено на NVIDIA GT730: все поля управления
   питанием возвращают `N/A`).
3. **Встраивание QUBO→Ising через вспомогательный спин** для переноса
   члена локального поля (h), когда ядро Ising фиксированной
   размерности (`sbm_ising`, 64 спина) реализует только член связи
   (J) — и всегда проверять соглашение о знаке энергии (E против -E)
   против реальной динамики ядра, а не только документации; ошибка
   знака дала внешне стабильный, но неверный результат, случайно
   проходивший модульные тесты на CPU.
4. **Предотвращение TDR (device lost) драйверов мобильных GPU
   Android через разбиение на батчи** (дробление крупных диспатчей на
   более мелкие суб-батчи) — настольные GPU допускают крупные
   единичные диспатчи, мобильные — не обязательно.
5. **AEAD-шифрование + защита от повторов/подделки**
   (`SecureChannel`) для ненадёжной передачи результатов worker→
   координатор в схемах распределённых волонтёрских вычислений, плюс
   персистентный write-ahead log + обёртка избыточной многопутевой
   отправки (`transaction_log` + `redundant_transmission` из
   `RS-SmartTCP`) для «не терять данные, даже если все пути отправки
   отказали».
6. **Вычисление чётности RAID6/Z2 по Рида-Соломона GF(2^8),
   выгруженное на GPU/NPU** (D3D12/DirectML на Windows, Vulkan
   иначе) через существующую инфраструктуру `open-raid-z` — включая
   автоматическое определение ускорителя с откатом на CPU.
7. **Поставка бинарников шейдеров через `include_bytes!` вместо
   загрузки файлов во время выполнения**, для кроссплатформенных
   исполняемых файлов (избегает проблем с путями `adb push` на
   Android при отдельных файлах `.spv`).

**Важная оговорка**: Этот проект — репозиторий концепции/PoC на
стадии пре-альфа — само видение «гибридного ядра» не реализовано,
существуют лишь изолированные PoC для GPU/RAID/сети. Это следует
чётко раскрывать при любом переносе.
