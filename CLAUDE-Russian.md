# Философия разработки и правила окружения (DreamOS / dream-os)

> **Примечание**: Это сжатый перевод текущего состояния. Полный
> исторический журнал изменений HANDOFF по-прежнему доступен только
> на японском языке (для краткости) в [CLAUDE.md](CLAUDE.md) —
> обращайтесь туда за деталями отдельных сессий.

Рабочий диск: `F:\runo`. Этот раздел следует практике использования
соответствующего раздела `CLAUDE.md` проекта
[`open-raid-z`](https://github.com/aon-co-jp/open-raid-z) как эталона.
Репозиторий GitHub: [aon-co-jp/dream-os](https://github.com/aon-co-jp/dream-os).

**Начало концепции: 2026-08-06** (сам пустой репозиторий GitHub был
создан ещё 2026-07-01, та же схема, что и у `open-directx`).

## Роль этого проекта (концептуальная стадия, кодом являются только отдельные PoC)

**DreamOS** нацелен на **гибридное ядро Linux и TRON OS**, призванное
объединить большинство существующих в мире операционных систем —
Windows PowerShell, приложения macOS/iPhone и приложения Android
должны работать на едином ядре с сохранением совместимости. Будущие
цели включают поддержку Sony PlayStation 5/6 и Nintendo Switch 2.

## Техническое исследование (2026-08-06, честное резюме)

Поиск на японском и английском языках в Google/GitHub **не выявил
существующей реализации**, воплощающей изначально задуманную идею
«гибридного ядра Linux×TRON с нативным запуском приложений всех
платформ». Главный вывод: **по состоянию на 2026 год не существует
практического способа нативно запускать приложения iOS на устройствах
не от Apple** (сама Apple блокирует JIT-компиляцию и виртуализацию
для сторонних приложений на уровне системы). Подход `crosvm` в
ChromeOS (общая база VMM для Linux через Crostini и Android через
ARCVM) оказался наиболее устоявшимся и реалистичным прецедентом. seL4
+ Genode/Neptune OS («микроядро + личность ОС») — ещё один
ориентир. Подробности, включая собственный анализ мейнфреймов (IBM
z/OS / Hercules / AWS Mainframe Modernization), см. в разделе
"技術調査結果" в [CLAUDE.md](CLAUDE.md).

## Целевые платформы (дорожная карта, по состоянию на 2026-08-17)

**Этап 1 (оборудование есть, начало сейчас)**: Windows (ПК с NVIDIA
GT730) и Android (несколько смартфонов).

**Этап 2+ (отложено, зависит от будущих лицензий)**: macOS/iPhone/
**iPad** (iPad добавлен 2026-08-17), различные дистрибутивы Linux/
UNIX, Sony PlayStation 5/6, Nintendo Switch 2/**3** (Switch 3 добавлен
2026-08-17), а также **совместимость с мейнфреймами IBM (z/OS)**.

**Честное раскрытие**: Поддержка macOS/iPhone/iPad, PS5/6 и Switch
2/3 требует непубличных SDK, соглашений о неразглашении (NDA) и
оборудования для разработки от соответствующих владельцев платформ —
ничего из этого в данной экосистеме сейчас нет. **Switch 3 официально
не анонсирована Nintendo по состоянию на 2026-08-17** — упоминание
здесь лишь заполнитель на случай «если/когда будет анонсирована», не
основанный на реальной информации о продукте. По мейнфреймам IBM:
эмулятор системы команд Hercules — это открытое ПО и технически
интегрируем, но для работы настоящей z/OS требуется официальная
лицензия IBM (отсутствует). «Мейнфрейм-версия AWS» оказалась сервисом
миграции приложений (AWS Mainframe Modernization / AWS Transform for
mainframe), а не слоем совместимости ОС.

## Реализованные PoC (верифицированы на реальном оборудовании,
Windows GT730 + Android Adreno 619)

- **`crates/dream-os-kernel`** (повторно использует `opencuda-vulkan`
  из `open-cuda`): общая база выполнения Vulkan для Windows/Android
  (ядро `vector_add`), управление энергопотреблением в стиле
  mining-OS (`MiningPowerProfile` + ядро double-SHA256
  `sha256d_mine`, результаты GPU верифицированы против эталона CPU на
  обеих платформах), комбинаторная оптимизация в духе Simulated
  Bifurcation Machine (SBM) Toshiba (ядро `sbm_ising`, баллистический
  SB-алгоритм, GPU/CPU сходятся к идентичной конфигурации спинов),
  конкретное применение задачи о рюкзаке на основе `sbm_ising`
  (выбор задач, `task_scheduler.rs`), мост DXBC→SPIR-V из
  `open-directx` (`directx_bridge.rs`), а также мост fused flash
  attention из `open-cuda` (`flash_attention_bridge.rs`, игрушечный
  размер 8×16).
- **`crates/dream-os-raid-bridge`** (повторно использует `RaidZVdev`
  + `zfs_accel_hlsl` из `open-raid-z`): мост ускорения чётности
  RAID6/Z2, верифицированное реальное ускорение на GPU (без отката на
  CPU), 8-страйповый roundtrip и самовосстановление после
  смоделированного повреждения одного диска, плюс демо, запускаемое
  одной командой.
- **`crates/dream-os-wire`** (повторно использует `SecureChannel` из
  `open-web-server-wire` + `redundant_transmission`/`transaction_log`
  из `RS-SmartTCP`): передача результатов с AEAD-шифрованием,
  устойчивая к повторным атакам и подделке, для концепции World
  Laboratory (распределённые волонтёрские вычисления), плюс
  персистентность `aruaru-db` (ACID-совместимая), верифицированная
  против реального экземпляра `aruaru-server`.

## Место в экосистеме

Связь с [`open-directx`](https://github.com/aon-co-jp/open-directx)
(кроссплатформенный слой совместимости DirectX, в настоящее время
высший приоритет в экосистеме), [`open-cuda`](https://github.com/aon-co-jp/open-cuda)
(CUDA-совместимые GPU-вычисления, реальный бэкенд Vulkan) и
[`aruaru-llm`](https://github.com/aon-co-jp/aruaru-llm) (LLM-инференс
через ядра Vulkan `open-cuda`). Точный способ интеграции пока
открыт — `dream-os` намеренно развивается небольшими, независимо
верифицируемыми шагами, пока завершение `open-directx` остаётся
приоритетом.

## Текущее состояние

Указанные выше PoC верифицированы на реальном оборудовании, но сам
DreamOS (единое ядро, координатор World Laboratory) по-прежнему
находится на стадии концепции/проектирования. Полный исторический
журнал HANDOFF см. в [CLAUDE.md](CLAUDE.md).
