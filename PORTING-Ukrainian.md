# PORTING.md — Посібник з перенесення dream-os (стисла версія)

> **Примітка**: Це стислий переклад. Повний посібник з дерева файлів
> та залежностей шляхів залишається доступним лише японською мовою
> (з домішками англійської) в [PORTING.md](PORTING.md) — звертайтеся
> туди перед реальним перенесенням.

**Обсяг**: `dream-os` — репозиторій на концептуальній стадії для шару
прикладних сервісів / шару абстракції GPU для Windows, macOS, Android
та різних дистрибутивів Linux (з Sony PlayStation 5/6 та Nintendo
Switch 2 як майбутніми цілями).

Підсумок повторно використовуваних шаблонів реалізації з цього
проєкту, на випадок перенесення їх в інший проєкт:

1. **Повторне використання наявних кросплатформних бекендів Vulkan**
   (`opencuda-vulkan` з `open-cuda`) як спільного шару виконання
   замість написання нових ядер з нуля — шаблон повторного
   використання через залежність за шляхом, який `dream-os-kernel`
   застосовує послідовно.
2. **Програмне керування duty-cycle живлення**
   (`MiningPowerProfile`) як нейтральна щодо виробника альтернатива
   API обмеження потужності на кшталт NVML, коли цільовий GPU їх не
   надає (підтверджено на NVIDIA GT730: усі поля керування живленням
   повертають `N/A`).
3. **Вбудовування QUBO→Ising через допоміжний спін** для перенесення
   члена локального поля (h), коли ядро Ising фіксованої розмірності
   (`sbm_ising`, 64 спіни) реалізує лише член зв'язку (J) — і завжди
   перевіряти конвенцію знаку енергії (E проти -E) щодо реальної
   динаміки ядра, а не лише документації; помилка знаку дала зовні
   стабільний, але хибний результат, який випадково проходив модульні
   тести на CPU.
4. **Запобігання TDR (device lost) драйверів мобільних GPU Android
   через розбиття на батчі** (поділ великих диспетчів на менші
   суббатчі) — настільні GPU допускають великі одиничні диспетчі,
   мобільні — не обов'язково.
5. **AEAD-шифрування + захист від повторів/підробки**
   (`SecureChannel`) для ненадійної передачі результатів worker→
   координатор у схемах розподілених волонтерських обчислень, плюс
   персистентний write-ahead log + обгортка надлишкового
   багатошляхового надсилання (`transaction_log` +
   `redundant_transmission` з `RS-SmartTCP`) для «не втрачати дані,
   навіть якщо всі шляхи надсилання відмовили».
6. **Обчислення парності RAID6/Z2 Ріда-Соломона GF(2^8), винесене на
   GPU/NPU** (D3D12/DirectML у Windows, Vulkan інакше) через наявну
   інфраструктуру `open-raid-z` — включно з автоматичним визначенням
   прискорювача з відкатом на CPU.
7. **Постачання бінарників шейдерів через `include_bytes!` замість
   завантаження файлів під час виконання**, для кросплатформних
   виконуваних файлів (уникає проблем зі шляхами `adb push` на
   Android з окремими файлами `.spv`).

**Важлива застереження**: Цей проєкт — репозиторій концепції/PoC на
стадії пре-альфа — саме бачення «гібридного ядра» не реалізоване,
існують лише ізольовані PoC для GPU/RAID/мережі. Це слід чітко
розкривати за будь-якого перенесення.
